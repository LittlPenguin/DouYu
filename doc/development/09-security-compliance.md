# 09. 安全与合规

## 目标

豆屿 Doyu 面向中国大陆用户，包含社区、AI、商城、支付和玩家交易。安全与合规是上线前置条件，不是后期优化项。

## 隐私与权限

客户端权限必须最小化。

| 权限  | 用途            | 策略                  | P1 状态                                                                                                                                           |
| --- | ------------- | ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| 相机  | 拍照生成拼豆图、发帖、头像 | 使用时申请               | ✅ 已在 AndroidManifest 声明 CAMERA + uses-feature required=false                                                                                    |
| 相册  | 选择图片          | 优先 Photo Picker     | ✅ 已使用 Photo Picker，无需 READ_MEDIA_IMAGES                                                                                                         |
| 通知  | 订单、评论、AI 完成提醒 | 用户触发场景后申请           | ✅ 已在 AndroidManifest 声明 POST_NOTIFICATIONS                                                                                                      |
| 网络  | 访问 API、上传、支付  | 必需                  | ✅ networkSecurityConfig：生产 HTTPS only；debug 通过 Gradle 从仓库根目录 `.env` 的 `DOUYU_ANDROID_CLEARTEXT_HOSTS` 生成 HTTP 白名单；不得把开发机 IP 明文放行写入 main/release |
| 存储  | 保存导出图纸        | 优先系统分享和媒体选择器，避免广泛权限 | ✅ 未申请广泛存储权限                                                                                                                                     |

隐私政策必须说明：

- 收集哪些信息。
- 信息用途。
- 保存期限。
- 第三方 SDK。
- 用户注销方式。
- 图片和 AI 生成记录处理方式。
- 支付和订单信息处理方式。

## 公开接口（免登录）

以下接口通过 Spring Security `permitAll` 配置允许未登录访问：

- `POST /api/v1/auth/register` — 邮箱密码注册，成功后直接登录
- `POST /api/v1/auth/login` — 邮箱密码登录
- `POST /api/v1/auth/refresh` — 刷新 token
- `POST /api/v1/admin/auth/login` — 后台登录
- `POST /api/v1/payments/callbacks/**` — 支付回调
- `GET /api/v1/posts/feed` — 推荐 Feed
- `GET /api/v1/posts/following` — 关注 Feed
- `GET /api/v1/posts/*` — 帖子详情（仅 GET）
- `GET /api/v1/products` — 商品列表
- `GET /api/v1/products/*` — 商品详情
- `/uploads/**` — 上传文件访问

所有其他接口必须携带有效 access token。

## 登录流程

登录方式：邮箱 + 密码。

客户端校验：

- 邮箱必须符合基础邮箱格式，入库前 trim 并 lowercase。
- 密码长度为 8-64 位；注册时确认密码必须一致。

请求字段：

- `email`：邮箱。
- `password`：密码。
- `confirmPassword`：仅注册提交，用于二次确认。
- `nickname`、`ageGroup`：仅注册提交。

> 长期目标是年龄段、未成年人状态和玩家卖家资格由后端根据实名信息或后端规则判定。该目标需要单独补实名或账号安全流程，当前不能当作已完成事实。

未登录用户访问需登录功能时，客户端弹出 `LoginRequiredDialog` 引导登录，支持场景：发帖、加入购物车、查看购物车、查看个人中心等。

## 密钥安全

禁止：

- 客户端硬编码 AI Key。
- 客户端硬编码 OSS Secret。
- 客户端硬编码支付私钥。
- 提交真实证书和商户密钥。
- 日志打印 token、邮箱、手机号、身份证号、支付敏感信息。

要求：

- 服务端密钥通过环境变量或密钥管理服务注入。
- 日志脱敏。
- 后台操作审计。
- API 全站 HTTPS。

## 内容审核

审核对象：

- 昵称。
- 头像。
- 简介。
- 帖子。
- 评论。
- 私信。
- 商品。
- 玩家定制服务。
- AI 输入。
- AI 输出。

审核结果：

- 通过。
- 拒绝。
- 仅自己可见。
- 进入人工审核。

公开展示前必须完成必要审核。被举报内容达到风险阈值后应自动降权或隐藏，等待人工处理。

## 未成年人保护

默认用户边界为 16+。

规则：

- 注册接口接收 `ageGroup`，长期应改为由后端根据实名信息或后端规则判定年龄段和未成年人状态。
- 16-17 岁用户标记为未成年人。
- 未成年人不得作为玩家卖家。
- 未成年人不得发布定制服务。
- 未成年人高额消费需要限制或二次确认。
- 不设计诱导沉迷的连续任务。
- 提供监护人投诉入口。

## 生成式 AI 合规

AI 功能必须遵循：

- 输入审核。
- 输出审核。
- 生成内容标识。
- 生成记录可追踪。
- 用户可举报 AI 结果。
- 禁止生成违法、不良、侵权内容。
- 根据业务属性评估算法备案和安全评估要求。

AI 生成结果用于公开社区前，必须按社区内容再次审核。

## APP 备案

中国大陆应用市场上线前准备：

- 主体资质。
- 域名备案。
- 服务器接入信息。
- App 名称。
- 包名。
- 图标。
- 应用分类。
- 隐私政策链接。
- 用户协议链接。
- 权限说明。
- 第三方 SDK 清单。

备案材料由运营、法务、技术共同确认。

## 支付合规

要求：

- 自营商品由平台承担交易责任。
- 玩家交易第一版不做自建资金池。
- 不做平台余额。
- 不做虚拟币现金兑换。
- 支付回调验签。
- 退款可追踪。
- 订单和支付日志保存。

如后续做分账、提现、担保交易，需要单独补充资质、税务、支付服务商和用户协议方案。

## 版权与投诉

风险内容：

- 明星照片。
- 动漫角色。
- 游戏角色。
- 品牌 Logo。
- 影视作品图。
- 他人原创图纸。

产品要求：

- 发帖声明原创、转载、学习交流或可商用。
- 玩家定制服务不得承诺侵权商业用途。
- 提供版权投诉入口。
- 投诉内容先限制传播，再人工审核。
- 重复侵权账号限制发布或封禁。

## 账号注销

注销要求：

- 用户可在 App 内申请注销。
- 注销前提示影响范围。
- 未完成订单、退款、纠纷时限制立即注销。
- 注销后个人资料脱敏。
- 法规要求保留的订单、支付、安全日志按规定保留。

## 安全测试要求

必须覆盖：

- 越权访问。
- 订单金额篡改。
- 支付回调伪造。
- 上传恶意文件。
- 文件直链越权。
- 私信骚扰。
- 评论刷屏。
- 举报滥用。
- 未成年人绕过卖家限制。
- AI 输入输出违规绕过。
