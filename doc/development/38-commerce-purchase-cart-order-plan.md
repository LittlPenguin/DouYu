# 38. 商品购买、购物车与下单计划

## 目标

实现保留的自营商品购买链路，不接入真实支付：

- 商品详情页加载真实后端商品。
- 用户选择的数量不得超过可用库存。
- 用户可以把自营 SKU 加入后端购物车。
- 用户可以从当前 SKU 立即创建订单，也可以从购物车商品创建订单。
- 创建后的订单保持后端状态 `CREATED`；客户端不得展示支付页面、支付结果、渠道交易号、退款状态或虚假支付成功。

## 后端契约

- `POST /api/v1/cart/items` 合并同一用户同一 SKU 的数量，并校验商品为自营、可见、在售，且请求总数量不超过可用库存。
- `PATCH /api/v1/cart/items/{itemId}` 按当前可用库存校验新数量。
- `GET /api/v1/cart` 返回购物车行，包含商品标题/图片、SKU、数量、行金额和过期/不可用状态。
- `POST /api/v1/orders` 接受两类输入：购物车下单的 `itemIds`，或立即购买的 `items`。
- `POST /api/v1/orders` 要求真实请求地址快照，字段包含 `recipient`、`phone`、`region`、`detail`。地址管理继续保留，但当前详情页购买链路可以提交手动输入的快照，不得提交假地址 ID。
- 创建订单会锁定 SKU 库存并写入订单商品。购物车下单只在订单创建后移除已提交的购物车商品。
- 取消 `CREATED` 订单会把状态改为 `CANCELED`，并释放该订单商品锁定的库存。
- 创建订单适用幂等。复用相同 `Idempotency-Key` 会返回原订单响应，不得重复锁库存或重复写订单商品。

## Android 契约

- 商品详情页只为 `SELF_OPERATED`、在售且有库存的 SKU 展示数量控件。
- 数量控件必须限制在 `1` 到当前可用库存之间。
- 商品详情页“加入购物车”前必须读取当前购物车，并把同一 SKU 已有数量计入库存上限；例如库存 12、购物车已有 5 时，本次最多还能加入 7，超出时必须在前端拒绝并展示自然中文提示。
- 购物车页更新数量时必须把行数量限制在当前 SKU 库存内；达到库存上限后继续增加时展示“已达到库存上限”等中文业务提示，不提交超库存更新。
- “加入购物车”必须调用后端购物车 API，并且只在后端响应成功后展示成功状态。
- “提交订单”在详情页收集手填收货信息，并提交后端立即下单请求。
- 商品详情、购物车、结算、收货信息、数量和订单创建相关 UI 文案必须使用自然中文；后端枚举值和 API 字段名保持不变。
- 如果后端库存保护仍返回 `409`、`Insufficient stock` 或类似冲突响应，Android Repository/Activity 层必须转换为中文业务提示，不能把 HTTP 状态码或英文错误直接展示给用户。
- 未登录、SKU 不可用、玩家商品、缺少地址和网络错误必须渲染明确状态；不得使用本地虚假购物车或订单数据。
- 商品详情页可以在创建订单后展示返回的订单 ID/状态，但不得跳转支付页面或暗示支付完成。

## 验证

- 后端测试覆盖购物车数量校验、立即下单、购物车下单、幂等、库存锁定和取消订单释放库存。
- Android 单元测试覆盖购物车/订单 API 的 Retrofit 注解和 repository 请求映射。
- Android 单元测试覆盖“库存 12、购物车已有 5、本次尝试加入 12”时前端拒绝并提示最多还能加入 7，以及购物车行数量达到库存上限后继续增加不提交超库存更新。
- Android 源码检查证明没有引入 Kotlin、Compose、本地 mock 或支付运行时入口。
- Android 中文文案测试覆盖商品详情、购物车、收货信息、数量和订单创建关键文案。
- 完成声明前必须运行完整相关 Android 和后端测试/构建命令。
