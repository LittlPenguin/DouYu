# 08. 商城、订单与地址管理

## 目标

商城和订单文档只描述当前保留的商品浏览、购物车、订单确认、订单状态展示、玩家商品直连边界和收货地址管理需求。支付、退款、对账、生产回调、真实微信/支付宝 SDK 或 API 不属于当前范围。

## 商城首页

Android 商城首页目标为真实后端商品驱动：

- 顶部分类 chip 来自 `GET /api/v1/product-categories`，固定包含推荐入口 `精选`，其余分类按后端公开商品聚合。
- `精选` 请求 `GET /api/v1/products?page=1&size=20`，其它分类请求 `GET /api/v1/products?page=1&size=20&categoryId=...`。
- 商品列表只展示 `status=ON_SALE` 且 `auditStatus=PASS` 的商品。
- 商品卡使用后端返回的 `imageUrl`、`imageWidth`、`imageHeight` 计算双列不等高瀑布流；无真实宽高时只能使用稳定 fallback，不允许用本地假图或假商品填充。
- 首屏不固定展示规则说明卡。交易边界、地址缺口和玩家商品边界在商品详情、订单确认和文档中表达。
- 验收数据必须来自后端/API/数据库流程，不得通过运行期 seed 自动插入。

## 商品类型

商品类型：

- `SELF_OPERATED`
- `PLAYER_SECOND_HAND`
- `PLAYER_CUSTOM_SERVICE`

商品状态：

- `DRAFT`
- `ON_SALE`
- `OFF_SALE`
- `SOLD_OUT`
- `DELETED`

SKU 必须包含：

- 规格名。
- 售价。
- 库存。
- 图片。
- 状态。
- 发货方式。

## 购物车

购物车规则：

- 购物车需要登录，未登录用户进入购物车时弹出登录引导。
- 只对自营商品提供标准购物车。
- 玩家二手和定制服务只展示信息、咨询入口或意向边界，不默认与自营商品混单。
- 缺货 SKU 要提示替代色或移除。
- 购物车不能用本地假商品填充空列表。

## 订单确认

订单确认页保留：

- 商品明细。
- SKU、数量、单价和服务端返回的金额字段。
- 收货地址区域。
- 地址缺口状态。
- 备注字段。
- 提交按钮的可用/禁用状态。

地址管理明确保留。当前若地址管理尚未闭环，订单确认必须展示收货地址缺口并禁用提交；不得用假地址、默认地址或静态地址绕过。

## 地址管理

地址管理需求保留：

- 地址列表。
- 新增地址。
- 编辑地址。
- 删除地址。
- 默认地址。
- 收货人、手机号、省市区、详细地址、邮编或地区扩展字段。
- 订单确认页选择地址。

地址字段属于当前保留范围，不得因删除地图/定位 Provider 而删除。地图选点、定位自动填充、第三方地图 SDK 或真实定位 Provider 不属于当前范围。

## 订单状态机

订单状态：

- `CREATED`
- `CONFIRMED`
- `FULFILLING`
- `SHIPPED`
- `COMPLETED`
- `CANCELED`

状态规则：

- 未确认或未履约订单可按服务端规则取消。
- 提交、取消、发货、完成等状态跳转由服务端控制。
- 客户端只能展示服务端状态，不得本地伪造成功状态。
- 当前范围不包含支付状态、退款状态、渠道交易号、对账状态或生产回调状态。

订单状态客户端展示标签：

| 状态 | 标签 |
|---|---|
| `CREATED` | 已创建 |
| `CONFIRMED` | 已确认 |
| `FULFILLING` | 备货中 |
| `SHIPPED` | 已发货 |
| `COMPLETED` | 已完成 |
| `CANCELED` | 已取消 |

## 玩家商品边界

玩家二手/定制商品只保留展示和直连沟通边界：

- 展示商品描述、图片、价格或意向价。
- 展示卖家信息和可咨询状态。
- 不承诺平台担保、资金托管、平台分账、提现或售后赔付。
- 不引入生产风控、黑名单、资金池、支付服务商、退款或对账需求。

## 验收重点

- 商城首页不使用本地假商品。
- 商品详情和订单确认从后端读取真实数据。
- 地址管理需求和地址字段仍在文档中保留。
- 地图/定位 Provider 不作为地址管理前置条件。
- 文档和设计图不再引用支付、退款、对账、生产回调、微信支付、支付宝支付或支付 SDK/API。
