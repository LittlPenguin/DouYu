# 豆屿 SpellBean 商业技术执行计划

## 当前定位

SpellBean 是面向 16+ 拼豆兴趣用户的 Android 社区与材料商城应用。当前阶段只保留：

- 社区内容发布、浏览、详情、评论和互动。
- 用户登录、注册、资料、关注、粉丝和消息。
- 商品浏览、购物车、订单确认、订单状态展示。
- 收货地址管理需求与地址字段。
- OSS-backed 图片存储、上传预签名/确认、Alibaba OSS 配置和后端联调能力。
- 后台、举报、审核状态和基础运营管理边界。

当前阶段明确不包含：

- AI 页面、AI 拼豆图纸、真实视觉 Provider、生成式大模型 Provider、AI 成本控制或 AI 内容安全。
- 地图 API、定位 Provider、地图选点或定位自动填地址。
- 支付、真实微信/支付宝 SDK/API、退款、对账、生产回调或渠道交易号。
- 真实 SMS Provider、生产限流、生产风控、资金风控。

- 完整合规文档，包括隐私政策、用户协议、SDK 清单、备案材料、投诉机制等。

OSS-backed 图片存储、上传预签名/确认、Alibaba OSS 配置和后端 upload/oss provider 保留，不属于本轮清理目标。

地址管理保留。删除地图/定位能力不影响收货地址列表、新增地址、编辑地址、默认地址、手机号、收货人、省市区、详细地址等需求。

## 用户价值

目标用户需要一个轻量、稳定、真实数据驱动的拼豆社区：

- 发现拼豆作品、教程和配色灵感。
- 发布自己的拼豆作品。
- 与作者、关注对象和粉丝互动。
- 浏览拼豆材料和玩家二手/定制商品信息。
- 在订单确认中维护收货地址，等待后续真实履约能力补齐。

第一阶段成功标准是社区、商城浏览、订单和地址管理基础链路清晰，不用 mock/demo 内容填充界面，不把未完成能力包装成已完成。

## 产品模块

### 社区

- 推荐、关注、教程、图纸、新手等频道。
- 双列瀑布流作品卡。
- 作品详情、图片轮播、作者信息、正文、话题和评论。
- 发帖、图片上传、评论图片上传、@ 和 # 结构。
- 空态、登录态、审核中、失败态必须清楚。

### 商城

- 商品分类来自后端。
- 商品列表来自后端真实商品数据。
- 商品卡展示图片、标题、类别、价格、库存和商品类型。
- 自营商品可进入购物车和订单确认。
- 玩家二手/定制商品只展示信息和直连沟通边界，不承诺平台担保或资金托管。

### 订单与地址

- 订单确认展示商品明细、数量、金额字段、备注和收货地址区域。
- 地址缺口必须阻止提交，不得使用假地址。
- 地址管理保留新增、编辑、删除、默认地址和订单选择地址。
- 订单状态只由服务端控制，客户端不本地伪造成功状态。

### 消息与通知

- 消息首页展示通知和私信摘要。
- 私信详情遵循互关、未互关限制和不可发送状态。
- 通知详情展示评论、互动、系统事件和审核状态。

### 我的

- 展示头像、昵称、简介、获赞、作品、关注和粉丝。
- 编辑资料保存现有资料字段。
- 城市/地区只允许手动资料字段或 UI 展示，不接地图定位。

### 设置

- 保留账号与安全、隐私与权限、通知设置。
- 不保留关于与完整合规材料页面。
- 权限页不声明位置、地图、生产合规或第三方 SDK 清单已完成。

## 技术原则

- Android 使用 Java + Activity/Fragment + XML。
- 不使用 Kotlin、Jetpack Compose、Compose Navigation、Kotlin serialization、coroutines 或 DataStore。
- 后端使用 Spring Boot 模块化单体。
- Runtime 数据必须来自后端；空 API 结果渲染空态、错误态、登录态或禁用态。
- 不使用静态 mock、demo 列表、假订单、假支付参数或本地样例内容填充屏幕。
- 图片上传和读取走后端签发上传 URL、确认接口和 OSS/OSS-backed 资源 URL。

## 阶段路线

### 阶段 1：Java/XML 基础与真实数据边界

- 清理 Kotlin/Compose 残留。
- 建立底部导航、主页面、登录注册、社区、商城、消息、我的页。
- 删除运行态 mock/demo 数据。
- 建立后端真实 API 空态和错误态。

### 阶段 2：社区详情与评论闭环

- 作品详情按 Open Design 还原。
- 评论输入、图片、@、#、禁用态和键盘状态可用。
- 真机截图证据记录实际覆盖范围。

### 阶段 3：商城、订单与地址管理

- 商城分类和商品列表由后端驱动。
- 商品详情、购物车、订单确认和地址缺口清楚。
- 地址管理字段和需求保留。
- 不接支付，不声明支付成功、退款、对账或回调能力。

### 阶段 4：消息、资料和设置收敛

- 私信、通知、我的页、编辑资料和设置页对齐 Open Design。
- 清理 AI、地图、支付和完整合规材料引用。
- 补齐文档、图稿和截图证据路径一致性。

## 验收标准

- `DouYu/app/src` 无 `.kt` 文件。
- Android 生产和测试源码无 Compose/Kotlin 引用。
- 后端 runtime seed/demo 内容不恢复。
- Android 构建和测试通过。
- 后端测试通过。
- Open Design screen parity 记录实际覆盖，不把缺失设备覆盖写成已通过。
- 文档、Open Design、diagrams 和 verification 不再把 AI、支付、地图、完整合规或生产 Provider 作为当前范围。
