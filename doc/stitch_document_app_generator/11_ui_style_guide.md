# 11. UI 风格与设计系统要求

## 目标

本分册用于约束豆屿 Doyu Android 客户端第一阶段 UI 方向。前端团队在进入 Compose 页面实现前，必须先读取本文件，并结合 `ui-ux-pro-max` 技能生成或复核设计系统。

UI 目标是：**年轻女性友好 + 轻卡通可爱 + 手作拼豆质感 + 现代社区商城 App**。

## 必用技能

前端 UI 开发前必须使用：

`D:\Studio\SpellBean\.codex\skills\ui-ux-pro-max\SKILL.md`

推荐执行方向：

```text
mobile social commerce handmade craft young female cute playful modern community ecommerce
```

技术栈检索使用：

```text
jetpack-compose
```

本次检索得到的方向可参考“社区、活力、手作、年轻化、块状信息组织”，但生成结果中的重紫色方案不作为豆屿第一版主视觉。豆屿应采用更轻、更耐看的女性友好配色。

## 视觉关键词

- 年轻女性为主。
- 轻卡通、轻可爱、轻手作。
- 有拼豆颗粒感，但不堆满装饰。
- 有社区亲近感，也有商城可信度。
- AI 拼图页面更有创作感和趣味感。
- 商城、订单、支付页面更克制，优先清晰和信任。

## 推荐配色

第一版建议使用浅色主题，避免暗色和高饱和主题作为默认体验。

| 用途 | 建议色彩方向 |
|---|---|
| 主色 | 柔和桃粉、珊瑚粉、豆沙粉 |
| 辅助色 | 浅薄荷、浅天蓝、暖米白 |
| 成功色 | 温和绿色 |
| 警示色 | 柔和橙色 |
| 错误色 | 清晰但不过饱和的红色 |
| 文本 | 深灰、近黑、低饱和紫灰或棕灰 |
| 背景 | 干净浅色，局部可用轻纹理 |

禁止将高饱和粉紫、重紫蓝渐变、奶油色、棕橙色作为全局主视觉。

## 组件风格

- 卡片圆角可以适中偏圆润，但不要所有区域都使用超大圆角。
- 按钮要明确可点击，主按钮优先使用实色或高对比色。
- 图标使用统一线性或面性图标，不使用 emoji 作为功能图标。
- 可使用拼豆颗粒、小贴片、小插画作为局部空状态或 AI 生成状态装饰。
- 底部导航可以有轻微可爱感，但必须保持识别清晰。
- 社区内容卡片要以图片和正文为核心，不让装饰抢走内容。
- 商品价格、库存、订单状态必须高可读。

## 页面差异化

| 页面 | UI 侧重点 |
|---|---|
| 社区 | 轻松、亲近、内容优先，适合浏览和互动 |
| AI 拼图 | 创作感、趣味感、过程反馈明确 |
| 商城 | 商品清晰、价格可信、购买路径直接 |
| 消息 | 信息密度适中，未读和风险提示清楚 |
| 我的 | 成长感、收藏资产、订单入口明确 |
| 设置 | 克制、清晰、合规入口容易找到 |

## 状态设计

每个核心页面必须覆盖：

- 加载中。
- 成功。
- 空状态。
- 失败。
- 未登录。
- 无权限。
- 审核中。
- 弱网重试。

空状态、失败状态、AI 生成中状态可以使用轻卡通插画。插画必须服务于状态理解，不得占据主要操作区域。

## 禁止方向

- 禁止做成儿童教育 App。
- 禁止堆满贴纸、气泡、渐变和装饰图形。
- 禁止使用 emoji 作为功能图标。
- 禁止文字挤压、重叠、横向滚动。
- 禁止为了可爱牺牲信息密度和可点击性。
- 禁止首页做营销落地页，第一屏必须是可用 App 体验。
- 禁止在商城、订单、支付页面使用影响信任感的过度卡通表达。

## 前端验收

- UI 能体现豆屿 Doyu，而不是 Android 默认模板。
- 375dp 宽度下文字不挤压、不重叠。
- 底部 5 个 Tab 识别清楚。
- 社区、AI、商城三类页面有差异，但属于同一套设计系统。
- 可爱感是轻量点缀，不影响长期高频使用。
- 页面中的图标、按钮、价格、状态、错误提示可读且一致。
